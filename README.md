# url-shortener

Self-hosted URL shortener on Cloudflare Workers. Single user, single Worker:

- `GET /` — admin UI (password sign-in) to create, list, edit, and delete short links
- `GET /{slug}` — public 302 redirect to the stored destination
- `POST /mcp` — MCP server (Streamable HTTP) so AI agents can manage links, secured by OAuth 2.1
- `GET/POST /api/*` — session-cookie REST API backing the UI

## Stack

| Piece | Choice | Why |
|---|---|---|
| Links storage | Cloudflare KV (`LINKS`) | Redirects are read-dominated point lookups; KV edge caching is the fastest fit. Slug→URL value + `createdAt`/`owner` in KV metadata. |
| OAuth state | Cloudflare KV (`OAUTH_KV`) | Required by `@cloudflare/workers-oauth-provider` (clients, grants, token hashes). |
| MCP transport | `agents/mcp` `createMcpHandler` | Stateless per-request Streamable HTTP — no Durable Objects, runs on the free plan. |
| Website auth | Password + HMAC session cookie | Single user, zero external dependencies. Password lives in the `ADMIN_PASSWORD` secret. |
| MCP auth | `@cloudflare/workers-oauth-provider` | OAuth 2.1 + PKCE, dynamic client registration (`/oauth/register`) and Client ID Metadata Documents. The same password signs you in on the consent screen. |

## Setup

```sh
npm install
npx wrangler kv namespace create LINKS       # paste id into wrangler.jsonc
npx wrangler kv namespace create OAUTH_KV    # paste id into wrangler.jsonc
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET   # optional: separate session-signing key
npm run deploy
```

## Develop

```sh
npm run dev          # wrangler dev
npm test             # vitest (runs in workerd via @cloudflare/vitest-plugin)
npm run typecheck    # regenerates worker-configuration.d.ts, then tsc --noEmit
```

For `wrangler dev`, put a local password in `.dev.vars`:

```
ADMIN_PASSWORD=local-dev-password
```

## Use the MCP server

Point any OAuth-capable MCP client at `https://<worker>.workers.dev/mcp`:

```sh
claude mcp add --transport http shortener https://<worker>.workers.dev/mcp
```

The client discovers `/.well-known/oauth-protected-resource`, registers itself dynamically, opens `/authorize` — sign in with your password, approve — and gets a token. Tools exposed: `create_short_link`, `list_links`, `get_link`, `update_link`, `delete_link`.

## Notes

- KV is eventually consistent (~60s worst case): a brand-new link can briefly 404 at far-away edge locations. Local PoP is fast.
- KV has no compare-and-set, so the slug uniqueness check is best-effort: two simultaneous creates of the same custom slug resolve last-write-wins. Fine for a single user; move to D1 if that ever matters.
- Destinations up to ~900 bytes are mirrored into KV metadata so listing costs one `list()` call; longer URLs fall back to a per-key read.
- Slugs: `^[A-Za-z0-9_-]{1,64}`; `api`, `oauth`, `mcp`, `authorize`, `login`, `logout`, `assets` are reserved. Random slugs are 7 chars, base62.
- Destinations must be http/https, ≤2048 chars, and may not point back at this host.
- `worker-configuration.d.ts` is generated by `wrangler types`, gitignored, and regenerated automatically before `npm run typecheck`. Never hand-edit it.
- Session: `__Host-session` HMAC-SHA256 cookie, 30-day TTL, signed with `SESSION_SECRET` when set, else `ADMIN_PASSWORD`. Setting `SESSION_SECRET` lets you rotate the admin password without invalidating sessions (and vice versa).
- Hardening optional: add a Cloudflare rate-limit/WAF rule on `/api/login` and `/authorize`.
